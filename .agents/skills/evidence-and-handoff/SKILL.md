# evidence-and-handoff

1. 수정된 파일과 커밋 SHA, 실제 통과한 테스트와 빌드 결과를 구분해 보고한다.
2. Android 소스 미작성 상태에서 APK를 만들었다고 주장하지 않는다.
3. APK 전달은 실제 GitHub Release의 직접 다운로드 링크로 한다.
4. 미확인 배민 화면의 접근성 노드 노출과 실제 사용감을 검증 완료라고 말하지 않는다.
5. 기능이 실패했을 때 정확한 제한사항과 수정 가능 범위를 간결하게 기록한다.
