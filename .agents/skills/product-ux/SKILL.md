# 제품 고유 경험의 추출 — 유형 사전 없음

1. 앱 이름·분야·기술 스택을 보고 기존 제품의 품질 기준을 복사하지 않는다. 실제 사용자의 목표, 가장 잦은 작업, 사용 환경, 성공의 징후부터 파악한다.
2. `docs/PRODUCT_BRIEF.md`의 일곱 관점을 참고하되 해당 없는 항목을 체크리스트로 강제하지 않는다. 필요한 관점을 추가한다.
3. 현재 프로젝트만의 중요한 경험적 성질 3~6개를 구체적으로 정한다. 예: 반복 조작 부담, 반응 지연, 화면 전환 중 연속성, 입력 정밀성, 정보 신뢰성, 감각/리듬 등. **예시가 곧 도메인 요구사항은 아니다.**
4. 각 성질을 사용자 관점의 상황·행동·관찰 가능한 성공 상태로 표현한다. 실제 데이터·핵심 상호작용과 연결하되 부적절한 정량 목표를 만들지 않는다.
5. 첫 화면의 주 행동, 보조 도구, 취소/종료, 요약/상세의 위계가 한눈에 이해되는지 확인한다.
6. 장기간 사용 감각, 작은 화면, 실제 입력, 키보드·시스템 영역, 자동화와 사용자의 수동 제어, 복귀/재방문을 **관련 있을 때만** 다룬다.
7. 품질 개선 명목으로 사용자 승인 없이 기존 동작·데이터·디자인을 변경하지 않는다. 실제 사용 검증이 없으면 미검증으로 표시한다.
