# risk-based-verification

1. 공유 URL 파서, 같은 shop ID 중복 방지, 모호한 상호 매칭 거부, 배지 스크롤 상태, ZIP 복원을 우선 시험한다.
2. 빌드/CI 성공을 실제 배민 앱의 접근성 동작 성공이라고 주장하지 않는다.
3. 데이터 마이그레이션·권한·서비스 복귀·서명 변경은 위험에 맞춰 추가 검증한다.
4. 사소한 수정에 무관한 전체 분석·테스트 반복을 요구하지 않는다.
5. 테스트 실패를 감추기 위한 기대값·제품 규칙 변경은 금지한다.
