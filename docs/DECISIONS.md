미검증 사실을 확정 완료로 승격하지 않는다. 새 기능의 방향을 변경할 때 사용자 요청을 우선한다.

## 결정·근거·승인 기록 원칙

제품 문서나 자동 테스트를 모델이 먼저 바꿔서 미승인 UX를 확정된 요구처럼 만들지 않는다.

| 구분 | 정의 | 처리 |
|---|---|---|
| 사용자 확정 | 요청·명시적 승인·이미 선택한 조작 방식 | 구현 계약. 변경 전 사용자 의도 재확인 |
| 코드에서 관찰 | 실제 파일 또는 기기 동작 | 사실로 기록하되 사용자 승인과 구별 |
| AI 제안(미승인) | 구현 중 떠오른 대안 | 현재 작업 범위에 포함하지 않음 |
| 미결정 | 실행에 필수인 정보가 없는 부분 | 가능한 구현은 진행하고 해당 부분만 표시 |
| 의도적 기술 부채 | 사용자가 편의를 위해 선택한 trade-off | 동일한 경고를 매번 반복하지 않음 |

새로운 중요한 결정이 생길 때만 날짜·출처·근거·영향을 추가한다. 기존 승인 UI, applicationId, 앱 데이터 및 개발 서명을 미승인으로 교체하지 않는다. 분석만 요청받은 경우 변경 0건을 유지한다.
