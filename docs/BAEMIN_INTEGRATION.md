# 배달의민족 연동 참고 — 정적 분석에서 확인한 개발 정보

이 문서는 **원본 배달의민족 APK/XAPK를 저장소에 올리지 않고**, 외부 보조 앱 개발에 필요한 사실·추정·실기기 검증 항목을 기록한다. 타사 앱 바이너리, 리소스, 역컴파일된 소스, 인증정보를 저장하거나 배포하지 않는다.

> 범위: 개인이 제공한 `배달의민족 16.27.1` XAPK의 메타데이터와 기본 APK DEX 문자열을 로컬에서 정적으로 확인했다. 앱 실행, 로그인, 공유 동작, 실제 네트워크 응답, 접근성 노드 수집은 수행하지 않았다. **이 파일은 앱 구현을 위한 참고 자료이며, 원본 APK의 재분석을 개발 착수 조건으로 삼지 않는다.**

## 2. 가게 식별 단서 — 정적 분석에서 직접 확인

기본 APK의 DEX 문자열에서 다음을 확인했다.

- `shopDetail_shopNo`, `shopNo`, `shopNumber` 문자열
- 공유 관련 문자열 `bm_rfr=SHARE`, `shopDetail_campaignId`
- 상세 메뉴 공유 문자열 예: `shopDetail/menuDetail?shopDetail_shopNo=%s&menuDetail_shopNo=%s&menuDetail_menuNo=%s&bm_rfr=SHARE&shopDetail_campaignId=%s&menuDetail_campaignId=%s`
- 클래스명 `FoodShopListFragment`, `FoodShopDetailFragment`, `ExternalRouterActivity`
- 로컬 DB 생성 문자열 `room_favoriteshop` 및 `shopNo TEXT NOT NULL` 기반 기본키

**해석:** 배민 내부에서는 가게 번호(`shopNo`/`shopNumber`)가 식별자 역할을 하는 구조가 확인된다. 그러나 내부 ID가 공유 앱에 그대로 전달되거나 접근성 노드에 노출된다고 확인한 것은 아니다. `shopNo`/ `shopNumber`가 모든 기능에서 같은 의미·식별 범위를 갖는지도 별도 검증이 필요하다.

### 공유 링크 입력 처리

- Android `ACTION_SEND` + `text/plain`을 수신한다.
- 공유 텍스트에서 URL 후보와 가게명 후보를 **자동 추출**한다. 링크만 존재해도 원문을 보존하고, 단축 링크·인코딩·쿼리 파라미터를 처리한다.
- `shopDetail_shopNo`, `shopNo`, `shopNumber`는 **파싱 후보**다. 모든 실제 공유 URL에 존재한다고 가정하지 않는다.
- `baemin.go.link` 문자열이 APK에 있으나 실제 단축 링크 형식과 리디렉션은 미검증이다. 확인이 가능할 때에만 제한된 HTTPS 리디렉션으로 URL을 해석한다. 비공개 API, 인증 쿠키, 원본 앱의 저장 데이터는 사용하지 않는다.
- 공유 원문·URL·가게 이름/지점명/고유번호 추출 성공 여부를 나누어 보관한다. 추출 가능한 필드는 자동 채우고 이미 등록된 매장은 중복 생성하지 않는다.
- **사용자가 매번 상호명을 입력하도록 설계하지 않는다.** 공유 텍스트에 상호가 없으면 공유 직전 짧은 시간 동안 유효하게 확보된 접근성 스냅샷의 가게명을 연결할 수 있는지 검증한다. 오인 위험이 있거나 이름을 끝내 확보할 수 없을 때만 입력·확인을 요구한다.
- 번호만 확보하고 이름을 모르는 상태에서 임의 상호명을 만들거나, 같은 상호의 다른 지점을 자동 병합하지 않는다.

### 저장/매칭

1. 저장된 가게 ID와 관찰된 가게 ID가 명확히 같은 경우 우선 매칭
2. 가게명 + 지점명을 정규화하여 정확히 비교
3. 사용자가 명시적으로 만든 별칭 비교
4. 다른 지점과 구별이 안 되면 자동 블랙리스트 배지 **미표시**

실제 배민 가게 목록의 접근성 트리에서 ID를 읽는다고 **미리 가정하지 않는다**. 등록 단계의 정확한 ID와 목록 화면의 텍스트 기반 매칭은 별개의 경로로 설계한다.

## 3. 내부 네트워크 경로 — 존재 확인만, 사용하지 않음

DEX 문자열에 다음 경로가 들어 있다.

- 가게 목록 관련: `https://shopdp-api.baemin.com/v4/{displayGroup}/shops`
- 가게 목록 관련: `https://food-curation-api.baemin.com/v4/{displayGroup}/shops`
- 가게 상세: `https://shop-detail-api.baemin.com/api/v2/shops/{shopNumber}/detail`
- 가게 리뷰: `https://review-api.baemin.com/v1/shops/{shopNumber}/reviews`

**기능 구현에 사용할 API 목록이 아니다.** 문자열의 존재만 확인했으며 요청 헤더·인증·응답 구조·현재 서버 동작은 검사하지 않았다. 독립 보조 앱은 배민의 비공개 API를 호출하거나 트래픽·HTTPS를 가로채지 않는다.

## 4. 접근성 기반 화면 인식 — 아직 실기기 검증 필요

사용할 Android API 및 동작은 이미 다음과 같이 확정되어 있다.

- `AccessibilityService`에서 대상 앱 화면 상태와 텍스트를 조회
- `AccessibilityNodeInfo`의 텍스트·노드 구조·화면 좌표 활용
- 목록/검색 결과의 카드 단위 가게 인식 및 **확실한 매칭만 표시**
- `TYPE_VIEW_SCROLLED` 수신 시 기존 배지 즉시 숨김
- 마지막 스크롤 이벤트 후 **약 180ms** 동안 추가 이벤트가 없으면 **현재 노드와 좌표를 새로 조회**한 뒤 배지 표시
- 배지를 스크롤 이동량에 맞춰 끌고 다니지 않는다
- 상세화면에서 정확히 식별한 가게의 경고/개인 메모 진입 표시
- 배민 이탈·서비스 종료·잠금 등 화면이 무효화될 때 이전 오버레이 제거
- 접근성으로 매장을 읽을 수 없는 화면에서는 **잘못된 배지보다 미표시** 선택
- 접근성 권한이 없거나 인식에 실패해도 직접 등록/메모/검색/백업 기능은 동작

**실기기에서 확인할 것:**

1. 설치된 앱 packageName과 XAPK 참고값 일치 여부
2. 가게 목록·검색 결과·상세화면의 접근성 노드에 상호/지점명이 있는지
3. 가게 카드별 노드 상하 관계와 `getBoundsInScreen()` 좌표의 정확도
4. 빠른 스크롤·관성 스크롤에서 이벤트 도착과 배지 잔상 여부
5. 배지가 원래 앱의 스크롤·터치·결제 동작을 방해하지 않는지
6. 실제 `ACTION_SEND` 텍스트/URL에 상호·지점·ID가 어떻게 들어 있는지
7. 단축 링크, 복수 지점명, 메뉴 공유 링크, 미등록 가게, 중복 등록 시 동작

### 개발 중 자료 수집 원칙

- 필요하면 보조 앱의 **개발자용 접근성 진단 화면**에서 화면 계층, 가게명 후보·좌표·이벤트 종류를 기기 로컬로 확인하도록 구현한다. 상시 수집·외부 전송·원문 무분별한 로그 저장은 하지 않는다.
- 개발자가 결과를 공유해야 할 때에도 전화번호, 주소, 개인 식별정보, 주문 내역, 인증 토큰을 제거한다.
- 코드가 준비되지 않았다는 이유로 사용자에게 배민 APK를 업로드하라고 요청하지 않는다. 정적 구조 정보는 위 단서로 충분하며, 실기기 동작 검증만 추후 필요하다.
