# Root cause before change
1. 관찰 증상·재현 조건과 이전에 정상 동작하던 커밋/화면을 정리.
2. 코드·스택트레이스·이벤트/상태 흐름을 읽어 실패 경계 특정. 재현 불확실하면 제한적 진단 추가.
3. 원인 가설을 **한 개**씩 증거와 맞춰 검사. 우연한 패치 후보 여러 개를 동시에 적용하지 않는다.
4. 수정은 책임 있는 상태/함수/경계에서 수행하고 임시 우회·오래된 실험 코드는 정리.
5. 재현 경로와 바로 인접한 회귀 경로를 검증. 사용자에게 수행하지 않은 기기 테스트를 했다고 주장하지 않는다.
6. 같은 문제가 여러 번 실패하면 '추가 workaround' 대신 사건의 전제(상태 소유권, Activity/task, iframe, async race, 플랫폼 지원)를 다시 점검.
7. 사용자가 '분석만' 원하면 변경 0건과 현재 검증 범위를 보고.
