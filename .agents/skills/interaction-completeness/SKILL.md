# Interaction completeness
각 주요 작업은 **발견→대상선택→실행→피드백→결과·저장→취소/복귀→재방문** 순서로 검토한다.
1. 실제 객체와 ID를 먼저 찾는다. 필요한 생성/보기/수정/삭제/복구만 구현; 모든 곳에 CRUD 강제하지 않는다.
2. 스크롤이 긴 모달/키보드/작은 화면에서도 닫기·확인·저장 접근 가능. 필요한 경우 본문 스크롤과 고정 footer 분리.
3. 버튼 onClick 유무보다 실제 persistence→UI refresh→재진입 확인. 색/크기/드래그의 미리보기와 commit 분리.
4. 하위 창 닫으면 부모 창·스크롤·선택·초안 보존. '뒤로'는 사용자가 예상한 계층으로.
5. 빠른 연타·느린 처리·실패/재시도에 중복 요청·이중 데이터 생성이 없는지 확인.
6. 현재 선택과 현재 위치, 실행 중과 완료, disabled와 오류의 시각적 의미 혼동 금지.
7. 버튼·메뉴가 있다면 접근성 이름과 충분한 터치 영역. 숨은 제스처만 유일 경로로 두지 않기.
