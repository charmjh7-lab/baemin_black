# scope-and-provenance

1. 우선순위: 최신 사용자 요청 > 승인된 제품 계약 > 검증된 코드 > 일반 지침.
2. 이미 확정된 스크롤 중 배지 숨김·정지 후 재표시를 다시 설계하지 않는다.
3. 개발 요청에는 실제 코드 변경으로 답하고 전면 분석을 반복하지 않는다.
4. 실기기에서 검증되지 않은 배민 접근성 노드 구조를 확정 사실로 만들지 않는다.
5. 요청하지 않은 대규모 UI 변경·기능 추가·서명 교체를 하지 않는다.
