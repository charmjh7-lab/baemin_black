# 상태·데이터·비동기·플랫폼·선택적 AI 계약

이 문서는 기술 스택과 제품 목적에 따라 필요한 부분만 적용한다. 특정한 문서 모델, 학습 알고리즘, 독서 위치, 타이머, 카테고리, 프롬프트를 새 제품에 이식하라는 의미가 아니다.

## 1. 데이터와 상태의 소유권

- 사용자가 계속 이용해야 하는 실제 객체·설정·진행 상황·선택·초안·현재 위치의 저장 책임과 복원 경계를 지정한다. 상태가 필요 없는 단순 화면에 불필요한 DB를 만들지 않는다.
- 앱·서버·OS·외부 서비스 가운데 어느 쪽이 무엇의 **권위 있는 원본**인지 정의한다. 동일 정보의 복제본이 서로 덮어쓰지 않게 한다.
- 동일 객체를 여러 화면·세션·비동기 요청이 참조하면 안정된 ID 및 필요한 버전/순서 정책을 둔다. 화면의 임시 배열 인덱스를 장기 식별자로 쓰지 않는다.
- 사용자가 저장·수정·삭제·공유한 결과는 UI뿐 아니라 실제 데이터에 반영되어야 하고, 실패·중단 뒤에도 일관되게 보여야 한다.

## 2. 작업·시간·비동기 오류 처리

- 작업마다 대기·실행 중·부분 성공·완료·실패·취소가 실제로 필요한지 정의한다. 상태 피드백 없이 멈춘 화면을 만들지 않는다.
- 중복 실행, 재시도, 늦게 도착한 결과, 앱 종료·재접속을 해당 데이터의 위험에 맞춰 처리한다(idempotency, transaction, request/version check 중 적절한 방법).
- 필요 없는 복잡한 이벤트 소싱·상태 관리 프레임워크를 기본 도입하지 않는다. 작업이 간단하면 단순하게 만든다.
- 최종 결과와 중간 미리보기, 편집 중 상태와 저장 완료 상태, 현재 표시와 사용자가 선택한 값을 구분한다.
- 정상 데이터가 남아 있는데 부가 기능 하나가 실패했다고 결과 전체를 폐기하지 않는다. 부분 성공을 살리고 오류를 설명한다.

## 3. 사용자 직접 조작과 자동 동작

- 입력 방법과 우선순위가 충돌하면 제품이 정한 사용자 의도를 지킨다(직접 선택·드래그·스크롤·탭 vs 자동 갱신/추천/이동).
- 드래그/확대/제스처/마우스·터치·펜·키보드 등은 실제 사용되는 입력에서만 충돌·좌표·commit·Undo를 평가한다.
- 긴 글·짧은 글·큰 데이터·실시간 변화 등 실제 입력 범위가 UI와 성능을 어떻게 바꾸는지 확인한다.
- 사용 시간·읽기 속도·진행 단계 등 **도메인에 해당하는 경우에만** 업데이트 시점, 백그라운드 정책, 진짜 완료 시점을 별도로 정의한다.

## 4. Android 앱일 때

- 실제 Activity/Task 구조에서 시스템 뒤로, 최근 앱, 화면 회전, 잠금·재개, 프로세스 복원, 외부 Intent, 권한 회수 중 관련 있는 경로를 설계한다.
- 외부 페이지·앱·공유·인증 뒤 복귀할 때 정확한 사용자 작업/대상 ID가 유지되도록 한다.
- 폴더블/화면 크기/시스템 바/키보드는 중요 행동을 가리지 않아야 한다. 버그 수정을 위해 미승인 UI 재설계를 하지 않는다.
- 기기별 제한이 있는 특수 OS UI·오버레이 등은 지원 여부 확인 전 '구현 보장'으로 약속하지 않는다.

## 5. Web·WebView·하이브리드 앱일 때

- 첫 화면 배경/테마와 콘텐츠 paint의 일관성, focus/blur, 다른 뷰로 복귀할 때의 중복 초기화·빈 화면을 확인한다.
- Native↔JS bridge, URL 공유, 탭·히스토리, 저장 객체 사이에서 같은 이벤트가 두 번 처리되거나 오래된 화면에 반영되지 않도록 한다.
- 보이지 않는 렌더러나 큰 캐시의 메모리 영향은 **실제 계측으로** 판단한다. 사용자가 보존하려는 세션을 임의로 지우지 않는다.

## 6. AI·모델을 실제로 사용하는 앱일 때

- 모델은 콘텐츠·추천·의미 분석을 생성할 수 있다. 삭제·금전·권한·영속 상태의 실제 반영은 앱/서버/사용자에게 적합한 검증과 권한 흐름을 거친다.
- 사용자 입력의 의미를 현재 UI 이벤트·열린 작업·대상 ID 등 명시적인 맥락과 연결한다. 단순 키워드만으로 작업 의미를 오판하지 않는다.
- 출처·입력 데이터·모델 원문·파싱 상태·사용자에게 표시한 결과를 구분하고, 필요한 경우 검토 가능한 증거를 만든다.
- 고정된 계산·검색·화면 이동에 무의미한 모델 호출을 추가하지 않고, 프롬프트 최적화로 본래 결과 품질을 손상시키지 않는다.
- 비밀 토큰이나 개인 원문은 사용자 동의 없이 진단·외부 공유에 포함하지 않는다.

## 7. 모든 기술 선택의 공통 원칙

현재 작동하는 설계·의존성·데이터·설정·계정·서명·업데이트 계약을 요청 범위 밖에서 바꾸지 않는다. 외부 스킬이 특정 프레임워크나 마이그레이션을 요구하더라도 해당 프로젝트에 필요하지 않으면 도입하지 않는다.

## 배민 블랙 적용 계약 (기존 프로젝트 명세 보존)


- UI/데이터: Compose + ViewModel + Room. 데이터베이스를 단일 source of truth로 사용.
- 서비스: AccessibilityService는 배민 패키지 이벤트만 처리. Debounce/throttle과 이전 작업 취소, 노드 재활용·정리.
- 화면 구분: 목록/검색 결과/상세/지원되지 않는 화면. 불명확한 화면에서 전 화면 오버레이 재활용 금지.
- 매칭: shop ID/상호+지점/명시적 별칭 순서. 모호한 값은 미매칭으로 반환. 사용자 메모를 잘못된 매장에 보여주지 않음.
- 위치: 노드 `getBoundsInScreen()`; 좌표계·가시 영역·회전·분할 화면 확인; 카드 밖 좌표면 표시하지 않음.
- 배지: `TYPE_ACCESSIBILITY_OVERLAY`, 비포커스·비터치. 스크롤 시작 시 즉시 제거, 정지 후 현재 배지만 재구성.
- 상세 경고: 임시 UI와 관리 앱 기록 화면 연결. 임의로 배민 클릭을 실행하거나 결제에 개입하지 않음.
- 공유: `ACTION_SEND`의 텍스트를 입력 자료로 처리. 허용된 HTTPS 호스트만 선택적으로 따라가고 리디렉션 및 시간 제한.
- 로컬 저장: Room 테이블의 ID·FK·유니크 키·삭제 규칙. 사진 파일 정리와 ZIP 복원 검증.
- 데이터 안전: 최초 DB 생성 이후 자동 파괴적 마이그레이션 금지. 버전/서명 유지.
- UI 쓰레드: DB/링크 확인/ZIP 입출력을 Main에서 수행하지 않음.
- 외부 권한과 사생활: 필요한 접근성 서비스 권한만, 화면 텍스트/메모 외부 전송 금지.
