# 사용자 경험 수용 원칙 — 화면이 아니라 실제 작업의 성공

이 문서는 **모든 앱에 공통인 UX 실패 방식과 검증 절차**를 규정한다. 제품별로 무엇을 해야 하는지는 `PRODUCT_BRIEF.md`의 사용자 행동과 품질 계약에서 파생한다. 과거 앱의 작업 시나리오를 새 앱에 복사하거나, 아래 항목을 모든 작은 수정에서 전부 테스트하지 않는다.

## 1. 의미 있는 작업은 시작부터 끝까지

| 관점 | 확인할 질문 | 실패를 구별하는 기준 |
|---|---|---|
| 발견 | 사용자가 다음 행동을 찾고 의미를 예상할 수 있나? | 화면에 있지만 알아보기 어렵거나 설명이 불일치 |
| 실행 | 입력·버튼·제스처가 올바른 대상을 처리하나? | 이벤트만 발생하거나 다른 객체를 변경 |
| 응답 | 처리·진행·완료·오류·사용 불가가 구별되나? | 눌러도 반응 없거나 중복 실행 |
| 결과 | 데이터·실제 콘텐츠·다른 화면·재진입 결과가 일치하나? | 임시 미리보기만 변하거나 결과가 사라짐 |
| 제어 | 취소·닫기·되돌림·뒤로가기·반복 수행이 가능한가? | 결과 확인을 강제하거나 원치 않는 경로로 이동 |
| 연속성 | 중단과 복귀 시 올바른 객체·위치·진행 맥락이 보존되나? | 새 작업으로 초기화, 기존 정보 삭제, 오래된 결과 덮어쓰기 |
| 실패 복구 | 느림·오프라인·권한 거부·오류·부분 실패에 대응 가능한가? | 일부 실패로 정상 결과까지 소실 |
| 실제 경험 | 제품 고유 성공 기준이 사용자의 맥락에서도 충족되나? | 코드와 화면은 정상이나 핵심 사용감이 좋지 않음 |

## 2. 조작이 보이는지와 실제 닿는지 구별

`닫기 버튼이 있다` ≠ `팝업을 언제든 쉽게 닫을 수 있다`. 단순히 DOM·Compose 트리에서 노드를 찾거나 탭 이벤트가 존재하는지만 확인하지 않는다.

- **닫기·취소·뒤로:** 긴 설명, 수십 개 항목, 전체 높이 스크롤을 내려야 겨우 도달한다면 발견/제어 실패. 화면 목적에 맞는 명확하고 일관된 경로를 제공한다. 시스템 뒤로가기만 암묵적으로 의존하지 않는다.
- **저장·확인·주 동작:** 작은 화면, 높은 글꼴 배율, 키보드 표시, 시스템 바·컷아웃, 가로 모드·폴더블 환경에서 가려지거나 손이 닿지 않으면 실패. 필요하면 스크롤 가능한 본문과 고정된 동작 영역을 나누되, 고정 영역이 본문을 덮지 않도록 한다.
- **스크롤의 사용성:** 사용자가 내용을 읽기 위해 스크롤할 수 있는 것과 필수 조작을 찾으려고 끝없이 스크롤해야 하는 것은 다르다. 모든 화면에 무조건 고정 footer를 만들지 말고 사용 목적·빈도·화면 높이와 작업의 위험을 고려한다.
- **중첩 팝업·편집:** 닫고 나서 부모 화면·선택 항목·입력 초안·스크롤 위치를 복원한다. 취소는 저장과 구별되어야 한다.
- **검증 장면:** 팝업 진입 직후, 긴 콘텐츠, 큰 글씨, 키보드 표시, 가장 작은 목표 화면 중 관련 있는 조건에서 **추가 스크롤 없이 핵심 닫기 경로를 찾고 실행**할 수 있는지 확인한다. 필수 확정 작업도 적절한 시점에서 접근 가능한지 확인한다.

## 3. 공통 UI·상태 품질

- **테마·대비:** 밝음/어두움, 선택·비활성·오류·로딩·모달·첫 프레임에서 콘텐츠와 조작이 보인다.
- **시각적 위계·문구:** 가장 중요한 행동과 정보를 먼저 인식할 수 있고, 부가 설명·반복 카드·무의미한 장식이 핵심을 가리지 않는다. 실제 필요한 문장과 장식성 문구를 구분하며, 같은 내용을 제목·설명·버튼에서 되풀이하지 않는다. 신규 UI의 표현 선택 근거는 `DESIGN_SYSTEM.md`에서 결정한다.
- **사용자 통제:** 자동 스크롤·포커스·추천·복원이 사용자의 현재 입력·제스처·직접 선택을 강제로 덮어쓰지 않는다.
- **화면 크기와 접근성:** 작은 폭·낮은 높이·글꼴 확대·키보드·안전 영역·터치 목표·스크린리더·포커스 순서 등을 실제 제품 환경에 따라 확인한다.
- **정확한 상태:** 현재 위치, 선택 항목, 작성 중인 초안, 진행 상태, 저장된 결과를 다른 개념으로 구별한다. 빠른 연타와 오래된 비동기 응답에 주의한다.
- **데이터 신뢰:** 갯수·합계·출처·내보낸 파일·복사/공유된 값·재진입한 콘텐츠가 화면과 일치한다.
- **외부/시스템 전환:** 외부 진입·권한·시스템 뒤로·회전·프로세스 복구 등 해당 플랫폼의 실제 경로에서 목적이 유지된다.
- **성능·감각:** 응답성·조작감·정보 처리 리듬·시각적 안정성·장시간 피로 등 그 제품에 중요한 감각 품질은 제품 계약으로 구체화한다.

## 4. 제품별 시나리오 도출 — 유형 분류 금지

1. `PRODUCT_BRIEF.md`의 **가장 중요한 사용자 작업 하나**를 선택한다.
2. 시작점, 입력·조작, 결과, 취소, 복귀를 실제 앱의 화면/객체/데이터 이름으로 짧게 연결한다.
3. 해당 작업을 실패시킬 가장 현실적인 **환경 변수 1~3개**(예: 긴 내용·느린 처리·좁은 화면·전환·권한·멀티 입력)를 선택한다. 없는 기능은 시나리오에 넣지 않는다.
4. 명확한 기대 결과와 관찰 가능한 증거를 남긴다. 반복해서 깨진 경험은 필요한 최소한의 회귀 검증으로 보존한다.

## 5. 검증 강도와 완료 주장

- 작은 수정: 직접 변경한 행동과 바로 인접한 회귀 한두 개만.
- 상호작용/데이터 구조 변경: 대상 ID→처리→실제 반영→재진입까지.
- UX 전체 개편: 화면의 발견·위계, 실제 사용자 작업, 화면 제약을 선택해 검증.
- 데이터 손실·인증·권한·결제·서명·중요 플랫폼 상태 변경: 위험에 비례한 추가 검증.

컴파일, 단위 테스트, UI 스냅샷, 기기 조작, 실제 사용자의 평가를 완료 보고에서 분리한다. 기기에서 보지 않았다면 기기에서 검증했다고 쓰지 않는다.

## 배민 블랙 구체적 수용 시나리오 (기존 계약 유지)


| 맥락 | 사용자 행동 | 완료 조건 |
|---|---|---|
| 권한 미부여 | 앱 실행 후 가게·메모 생성 | 접근성 권한 없이 데이터 관리 가능 |
| 가게 공유 | 배민에서 공유 → 배민 블랙 선택 | URL 수신, ID 있으면 추출, 없으면 수동 입력 |
| 중복 가게 | 같은 shop ID 다시 공유 | 중복 생성 없이 기존 기록 열기 |
| 검색 목록 | 블랙리스트 가게가 보임 | 정확히 식별 가능한 카드에만 배지 |
| 빠른 관성 스크롤 | 목록을 빠르게 이동 | 기존 배지 즉시 사라지고 이전 좌표에 남지 않음 |
| 스크롤 정지 | 약 180ms 정지 | 현재 노드·좌표 기반으로 새 배지 배치 |
| 매칭 불명확 | 같은 상호의 복수 지점 | 잘못된 가게 차단 표시 없음 |
| 상세 화면 | 등록 가게 진입 | 블랙리스트 경고/메모 진입, 이탈 시 제거 |
| 기록 | 추가·수정·삭제, 재방문 | Room에 정확히 지속 |
| 화면 전환 | 홈·잠금·다른 앱 | 오래된 오버레이 즉시 제거 |
| 복원 | 기존 기록이 있는 상태에서 ZIP 가져오기 | 원본 무조건 삭제하지 않고 충돌 처리 |

UI에 기능 버튼이 '존재'하는 것과 긴 메모·키보드·작은 화면에서 실제로 '누를 수 있는 것'은 별도 검증한다.
