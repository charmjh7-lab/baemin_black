# 과거 개발에서 도출한 재발 방지 패턴 — 범용 사례집

이 문서는 제품 유형별 요구사항이 아니라 **서로 다른 앱에서 반복된 실패의 메커니즘**을 정리한 참고 문서다. 특정 과거 제품·프로젝트·기능을 새 저장소로 옮기지 않는다. 현재 사용자 요구와 코드에서 실제 위험을 발견했을 때 해당 항목을 선택한다.

## 사람 눈에는 실패지만 코드에는 존재하는 문제

1. 필요한 버튼·수정·삭제·취소·복귀가 없음. 단, 관련 없는 모든 CRUD를 무조건 추가하는 것도 실패다.
2. 버튼은 존재해도 너무 깊은 화면·긴 스크롤 끝에 있어 보이지 않거나 키보드·시스템 바에 가려짐. **존재·클릭 이벤트 테스트는 접근성/발견 가능성 검사가 아니다.**
3. 입력 UI는 동작하지만 실제 저장·다른 화면 반영·재진입 후 복원에 실패.
4. 한 작업 후 목록·선택·스크롤·편집 초안이 예고 없이 사라져 다음 작업을 시작하지 못함.
5. 수동 입력·스크롤·선택을 자동 기능이 덮어쓰거나 조작 주체와 실제 결과가 일치하지 않음.
6. 작은 화면·큰 글씨·밝음/어두움·콘텐츠 길이·키보드·오류 상태를 보지 않고 기본 스크린샷만 확인.
7. 기능 목록을 나열하거나 카드·배지·넓은 공백으로 채워 첫 행동과 핵심 정보가 보이지 않음.
8. 제스처·터치·키보드·외부 입력의 우선순위, 미리보기와 최종 확정, Undo가 어긋남.
9. 사용자가 중요하게 느끼는 반응 속도·리듬·정밀도·조작 피로를 기능 존재와 별도로 평가하지 않음.

## 기술적으로 통과하지만 제품 경험이 깨지는 문제

10. 화면 이동·백그라운드·복귀·재생성 이후 현재 객체·작업·설정이 초기화되거나 오래된 위치로 돌아감.
11. 비동기 결과가 늦게 도착해 새 작업을 덮어쓰고, 연타·재시도에서 중복 데이터나 이중 호출 생성.
12. 빠른 화면 전환·첫 렌더·애니메이션 중에 흰 프레임·깜박임·팝업 같은 시각적 충격.
13. 일부 메타데이터/응답 파싱 실패가 정상 콘텐츠까지 폐기하는 전부 아니면 전무 처리.
14. 시스템/외부 서비스와 연결된 공유·인증·Intent·탭·창의 실제 진입 목적지를 확인하지 않음.
15. 숫자·아이템 개수·합계·출처·파일 내보내기의 의미와 실제 데이터가 어긋남.
16. 사용자 행동을 방해하는 불필요한 지연·확인·설정 단계; 반대로 주의 환기가 핵심인 제품에서 의도적 마찰을 제거.
17. 캐시·지연 처리·조건 우회로 증상은 감췄지만 원래 성능·상태·플랫폼 문제는 남음.
18. 새로운 기능이 기본 진입점에 연결되지 않거나 기존 인터페이스·데이터 모델과 어울리지 않음.
19. 디자인·모델·비용 최적화에서 이미 만족하던 핵심 품질·감각·말투·콘텐츠 수준을 잃음.

## 에이전트 운영과 완료 보고 문제

20. 버그 하나를 고치면서 관계없는 UI·테스트·제품 문서를 변경한 후 새 상태를 정답으로 간주.
21. 앱의 실제 기술 스택이나 플랫폼 지원을 확인하지 않고 일반 권장 스킬대로 전면 마이그레이션.
22. 전체 테스트·에뮬레이터·APK를 매번 빌드하면서 정작 사용자 핵심 여정을 검증하지 않음.
23. 빌드 성공을 실제 기기 사용·업데이트 설치·사용자 품질 검증 성공으로 잘못 보고.
24. 원인 증거 없이 패치를 여러 겹 쌓고 같은 실패를 계속 반복.
25. 과거 설계·AI 제안·임시 분석을 현재 사용자가 승인한 제품 요구로 오인.
26. 반복된 문제를 해결한다며 범용 프롬프트에 사례를 무한 추가해 서로 모순되고 무거운 규칙집을 만듦.

## 실제 적용 방법

- 초기 제품에서 `PRODUCT_BRIEF.md`의 목적과 사용 장면부터 확정하고, 거기에서 **제품 고유** 성공 조건을 만든다.
- 위 26개 중 현재 구현에서 실제로 발생 가능성이 높은 2~4개만 위험·검증 대상으로 선택한다. 제품에 없는 기능은 생성하지 않는다.
- `UX_ACCEPTANCE.md`의 행동/도달성/복귀 검증으로 전환해 **코드와 실제 화면 또는 테스트 가능한 동작**에 연결한다.
- 이미 해결한 증거를 재사용하고, 이 사례집을 읽었다는 이유만으로 새 문서·테스트·기능을 대량 생성하지 않는다.
